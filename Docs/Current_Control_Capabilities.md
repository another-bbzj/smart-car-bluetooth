# 当前小车运行能力与赛道元素完成度

> 版本：2026-11-13
> 适用分支：`menu`（已合并 `codex/vision-low-speed`）
> 前提：**假设香橙派图像代码完全正常**，能持续输出有效的曲率/观测帧；本文只评估 F407 下位机当前实际运行的控制能力。
> 注意：视觉联调文档明确说明“比赛任务状态机尚未实现”。本文不把“能跟随曲率”写成“能完成全部比赛任务”。

---

## 1. 当前运行链路

```text
5 ms PIT 中断（控制）
  ├─ 读编码器 -> Car_TickDt()
  ├─ 解析蓝牙/视觉 FIFO
  ├─ 手动模式：WHEELS/PID/HEARTBEAT/STOP
  ├─ 自动模式：AUTO_ARM + 视觉曲率 -> 左右轮目标
  ├─ 五次曲线参考规划 -> 双轮速度 PID -> PWM/方向
  └─ 保护：断链、堵转、方向、周期、控制器、视觉失效

主循环
  ├─ Car_Adc_Task()    电池电压采样，内部 50 ms 限速
  ├─ Car_Menu_Poll()   四键扫描、链表浏览/参数编辑
  └─ My_Vofa_poll()    100 ms 周期遥测
```

新增功能已正式调用：

- `Car_Main()` 初始化阶段调用 `Car_Adc_Init()`、`Car_Menu_Init()`；
- 主循环调用 `Car_Adc_Task()`、`Car_Menu_Poll()`；
- Keil 全量编译：**0 Error / 0 Warning**。

## 3. 当前能自动执行的控制功能

### 3.1 手动模式（蓝牙）

- `ARM`：进入 RUN；
- `WHEELS`：左右轮目标转速；
- `PID`：在线修改 Kp/Ki/Kd（放大 100 倍）；
- `HEARTBEAT`：500 ms 通信看门狗；
- `STOP`：任意模式立即停车、清故障。

控制链：五次曲线参考规划 → 双轮速度 PID → PWM/方向；带加速度/加加速度限制、输出限幅、抗饱和、堵转/方向/周期/断链保护。

### 3.2 低速视觉自动模式

- 启动命令：`CMD=6 AUTO_ARM`，载荷为轮胎直径 mm、轮距 mm、速度 mm/s；
- 只允许在 `STOP`、两轮实测 < 5 rpm、视觉新鲜有效时启动；
- 消费视觉曲率：
  - TYPE=1：左转正；
  - TYPE=3：原视觉右转正，固件取反后统一为左转正；
- 目标：`v_left/right = v × (1 ∓ curvature × track / 2)`，两轮同比缩放到最高 60 rpm；
- 拒绝 `|curvature| > 8/m` 或 `|curvature × track/2| > 0.8` 的急弯；
- 视觉无效、处理+接收年龄达到 100 ms、会话变化：锁存故障 7，清零输出；
- 自动模式拒绝 `WHEELS`；`STOP` 始终有效；
- 恢复视觉不会自动恢复行驶，必须人工 `STOP` 后重新 `AUTO_ARM`。

### 3.3 菜单与电压

- 四键链表菜单：建链、浏览、参数编辑（PID、卡尔曼、圈次、限速、低压阈值等）；
- 显示层暂时移除，菜单操作目前不便于肉眼观察；
- ADC 每 50 ms 采样，输出 `NORMAL / WARN / CUT`；可选 GPIO 报警；
- **目前没有把低压状态自动接入降速/停车**，需要控制层读取 `Car_Adc_IsLow()` / `Car_Adc_IsCut()` 后自行决策。

## 4. 赛道上能完成哪些元素

> 判定标准：F407 按视觉曲率自动行驶，**不包含**需要额外状态机/执行器的得分动作。
> “图像代码完全”指香橙派能给出有效曲率/观测；不等于下位机自动完成了赛题任务。

| 赛道元素 | 能否自动通过 | 说明 |
|---|---|---|
| 直道 | ✅ | 曲率≈0，速度闭环直行 |
| 普通弯道 | ✅ | 曲率跟随 |
| 连续弯 | ✅ | 连续曲率跟随；受 60 rpm 和 8/m 限幅 |
| 十字路口 | ✅（几何通过） | 只要视觉给出正确曲率；固件不识别“十字”本身 |
| 环岛 | ✅（几何通过） | 只要视觉给出进环/环内/出环曲率；固件不识别环岛状态 |
| 160 cm 断路 | ⚠️ 条件通过 | 视觉持续有有效曲率时可沿路径通过；一旦丢线/曲率失效，故障 7 停车，**没有盲行/航迹推算穿越** |
| 绿色路障 | ⚠️ 几何通过 | 若视觉把“直通”编码为直行曲率，可通过；固件无颜色识别/直通判定 |
| 黄色路障 | ⚠️ 几何通过 | 若视觉把绕行路径编码为曲率，可通过；固件无“禁止触碰/碾压”判定 |
| 红色路障第一圈 | ⚠️ 几何通过 | 若视觉给出直行曲率，可通过；固件不区分红障，不会主动“忽略” |
| 红色路障第二圈停车 5s | ❌ | 固件没有红障事件、停车 5s 计时和再起步逻辑 |
| 软件盲盒 | ❌ | 无盲盒触发、任务执行和完成判定 |
| 真正停车点 | ❌ | 无停车点识别/精确停车逻辑 |
| 数独采集/拼接/求解/显示 | ❌ | 固件只缓存四份子块（`Car_GetVisionTile`），没有拼接、求解和屏幕显示 |
| 自动发车/圈次切换 | ❌ | 没有比赛状态机；`AUTO_ARM` 需上位机手动发送 |
| 电池电压显示 | ❌ | 显示层移除；只有 ADC 状态位 |
| 低压自动降速/停车 | ❌ | 只有 `WARN/CUT` 标志，未接入控制策略 |

### 结论

**假设图像完全、且视觉把每个元素的期望路径都编码成曲率**，当前下位机可以自动完成：

> 直道、弯道、连续弯、十字、环岛的**几何跟随**；黄障/绿障/红障第一圈在视觉给出绕行或直行曲率时也能**物理通过**。

但当前下位机**不能自动完成**：

> 红障第二圈停车 5s、软件盲盒、真正停车点、数独拼接/求解/显示、自动发车/圈次切换、低压自动降速/停车，以及所有需要“识别元素类型并做得分动作”的逻辑。

## 5. 要完成整场比赛还缺什么

1. **视觉协议扩展**：元素类型、路障颜色、动作请求（停车/等待/完成）、数独结果；目前 TYPE=1/3 只给曲率。
2. **比赛状态机**：发车 → 第一圈竞速 → 路障分支 → 第一圈结束 → 第二圈低速 → 红障停车 5s → 数独 → 盲盒 → 真停车点 → 结算。
3. **160 cm 断路策略**：视觉丢线后的航向保持/航迹推算，或视觉端提供横跨断路的虚拟路径。
4. **数独后处理**：四子块拼接、6×6 求解、屏幕显示；目前只有子块缓存。
5. **低压策略**：`Car_Adc_IsLow()` → 降速，`Car_Adc_IsCut()` → 停车/联锁。
6. **显示层恢复**：按 LCD200 `LCD200_DIR_Cross` 的 320×240 横屏重新排版；当前 `Car_Menu_Render()` 为空实现。
7. **实车标定**：轮胎直径、轮距、编码器 CPR、相机标定、PID/前馈；这些不填，自动模式的物理路径仍会偏差。
